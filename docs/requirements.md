# CM 的需求与验收清单（feishu-card）

> **这个文件是唯一需求依据。** 每改一次卡片，改完必须回来逐条对本文件验收，
> 而不是改完就说"好了"。CM 原话（2026-09-15）：
> 「不行你就搞一个专门的项目文件，去记录我的要求，然后改完之后就看看能不能达到我的要求。
> 改来改去，改那么多次都改不对。」
>
> **规矩**：① 需求原话照抄，不许我改写成"我觉得你要的是"；② 每条都要有可执行的验收方式；
> ③ 状态只能由**证据**决定（快照 / 日志 / 真机截图），不许靠"应该可以了"。

---

## 一、需求清单

### R1 · 中途说的话必须显示（当前**不满足**，2026-09-15 修）

> CM 原话：「他中间的一些说的话，或者一些就是输出的一些不是深度思考的，就普通的思考的内容。
> 它会显示出来，但现在好像不显示了……就我还是得需要它显示出来的，
> **因为他中途说的一些内容，我可以根据他的这些内容去判断他有没有跑偏。**」

> CM 原话（复述，更精确）：「我说的是他中间的一些说的话，我也要看到，
> **不是他在后面思考的东西，而是他说『我要做什么，我要做什么。怎么样的一个状态，然后还要做什么』**，
> 这样的一些内容我是要看的，你现在完全搞没了。」

**要**：agent 干活的**阶段汇报**（"先查库" → "查到了，现在整理" → "接下来写文件"）→ 显示在卡片上。
**不要**：它的**内心独白 / 深度推理**（`Mystery solved — …`、`Now writing the summary…` 这类英文思考）。

**验收方式**
1. `interim_assistant_messages` 必须为 `true`（4 个 profile 都要）。
2. 真机发一条需要多步干活的指令 → 卡片上应能看到中文的阶段汇报，且它出现在工具摘要面板**之外**（独立正文段）。
3. 英文推理不应出现（`card_adapter._skip_as_interim_reasoning`）。
4. 证据：gateway.log 里该回合应有 `_interim_send` 的 `send()`；state.db 里该回合的 assistant 消息 `content` 非空。

**验收命令**
```bash
# ① 开关
grep -n interim_assistant_messages "$LOCALAPPDATA/hermes/config.yaml" \
  "$LOCALAPPDATA/hermes/profiles/feishu2/config.yaml" \
  "$LOCALAPPDATA/hermes/profiles/basketball/config.yaml" \
  "$LOCALAPPDATA/hermes/profiles/football2/config.yaml"
# ② 过滤层单测
python tests/smoke_live.py
```

### R2 · 工具调用必须能折叠，像 ZCode 一样（已满足，2026-09-15 修 R2b）

> CM 原话：「这些调用工具的指令是可以折叠的，就像 Zcode 一样可以折叠。
> 但现在只折叠了第一条，剩下的代码框……全部都是直接展示出来的」

**要**：所有工具调用进**同一个可折叠面板**，不是只折第一条、其余摊开。

**验收方式**
1. `tests/snapshot_card.py` 中 16 条工具调用的 `折叠=` 全为 ✓。
2. 心跳通知（「已持续工作 N 分钟」）插队之后到来的工具命令**仍然折叠**
   （`test_folding_survives_heartbeat_notice`）。
3. 真机：面板标题 `🛠️ 工具摘要 (N)`，`N` = 真实工具数；点击可整体折叠/展开。

### R3 · 工具摘要行要看得懂（已满足，2026-09-15 修）

> CM 原话：「我都不知道你搞的是什么东西，你自己去看一下 Hermes 最近跟我说话的那一张卡片，
> 里面的东西，我都不知道你怎么搞的。」

**要**：每行是 `- {状态} · {工具名} · {关键参数}`，例如
`- ⏳ · read_file · \`P:\Qoder\work\Ai100\obsidian\_hots.md\``。

**不要**：工具名变成字面量 `tool`、参数位放参数**键名**（`(['path'])`）、或把整段 JSON 塞进来。

**验收方式**
1. `python tests/snapshot_card.py --check` → exit 0（无无效行）。
2. `test_tool_line_never_degrades` 全过（all / verbose 两种上游形态都锁住）。
3. 真机：面板里每一行都能看懂"用什么工具、对什么目标"。

### R4 · 同一段内容不许分两张卡发、不许重复（已满足，2026-09-15 修）

> CM 原话：「他会回复 2 到多张卡片，然后这几张卡片大部分内容都是重复的。」

**验收方式**
1. `python tests/probe_invariants.py` 全过（含 I11 卡内不重复 / I12 跨卡不重复）。
2. 真机：一个回合**一张卡**（除容量换卡，换卡时旧卡只留一行指针、新卡不复制旧正文）。

### R5 · 以 ZCode 为准（方法要求）

> CM 原话：「你不用给我选，我告诉你我要的是什么。
> **zcode 是怎么样发过来的，你就给我改成什么样。你不懂，你就去看 zcode 的源码，去照抄。**」

**要**：卡片形态以 ZCode 实际行为为准；不确定就去读 ZCode 源码（`app.asar` → `out/host/index.js`），
不许靠猜、不许拿"我觉得这样更好"覆盖。

### R7 · 不许打补丁思维（方法要求，CM 反复强调）

> CM 原话：「你不要一直打补丁了，我真的是服了你了。」
> 「你不要总是想着我可以打补丁，总是有这种打补丁的思维是不对的。」

**要**：先盘清根因（有证据）→ 回退/重试 → 单点小改 → 最后才加机制（[[开发标准]] §8 最小化原则）。
**禁止**：在没搞清"为什么"之前叠加正则/开关/兜底。参见 [[教训检讨]] 015。

### R8 · 卡片状态行必须真实（2026-09-16 新增）

> CM 原话：「他们的卡片最后一句写着"回复中"或者"已完成"，但这个状态是不对的。
> 现在是没有针对这个状态去做措施，保证这个状态是正确的。」
> 具体表现：①「有时候他一直说"回复中"，其实他就不做事了，后台没在调用工具什么的。」
> ②「有时候他写"已完成"，但过一会就会再弹一些内容出来。」

**要**：
- 「✅ 完成」**只**在真实回合结束时出现（上游最终回复的 `notify=True`，或 `finalize=True`）；
- 回合仍在进行 → 显示进行中；**长时间无进展** → 明确写出"已 N 分钟无新动作"（诚实，不糊弄）。

**不要**：用"多久没新内容"**猜**完成（会提前误报）；也不要因为心跳而永久停在"回复中"。

**验收方式**
1. `test_status_is_truthful`（7 项）+ `smoke_live` ⑤ 端到端断言（`notify=True` 才封口）全过。
2. 真机：发一条会跑工具的活 → 中途不得出现「完成」；回合结束才变「✅ 完成」。
3. 若出现长时间无动作 → 末行应显示「运行中…（已 N 分钟无新动作）」。

**验收命令**
```bash
python tests/test_card_session.py | grep -A 8 状态必须真实
python tests/smoke_live.py --no-send | grep -A 4 状态真实
```
